SLA Floor vs. Multi-Objective Optimization

083 / Architecture
Reliability is enforced as an SLA feasibility floor (Option A), preserving single-objective tractability and avoiding arbitrary dollar-to-reliability trade-off hyperparameters.

Option A: SLA Feasibility Floor (Recommended & Adopted)

• Definition: C(t) = { m ∈ M : rel(m) ≥ R_min(t) ∧ lat(m) ≤ L_max(t) }

• Contractual Alignment: Reflects real enterprise SLAs (either compliant or breached).

• Mathematical Tractability: Preserves standard MCFLP-B form with valid Lagrangian dual bounds.

• No Tuning Noise: Zero arbitrary trade-off weighting factors.

Option B: Multi-Objective Weighted Cost

• Definition: min Cost - γ · Reliability

• Contract Breach Risk: Legal to sacrifice SLA compliance if dollar savings exceed penalty.

• Hyperparameter Sensitivity: Solvers swing radically based on arbitrary γ choice.

• Destroyed Duality: Breaks clean facility location decomposition.

Track A: Greedy Construction & Feasibility Lookahead

035 / Lead
Plain greedy fails under aggregate coupling; feasibility lookahead (A+M1) eliminates budget starvation but cannot overcome coupled task placement.

The Aggregate Coupling Trap (Finding F8)

• On adversarial fixture (3 tasks, 2 profiles):

• Plain greedy commits t1 and t2 to m1 individually.

• Misses that t1 and t2 together fit on m2, resulting in cost 300 vs. true optimum 280.

• Multi-start random restart does not escape the trap (F9).

M1 Feasibility Lookahead (Paper P3)

• Before assigning task t to profile m, checks that all remaining unassigned tasks have ≥1 admissible profile.

• Eliminates budget starvation on tight instances.

• Executes with zero asymptotic runtime overhead.

Conclusion & Committee Defense Q&A

035 / Lead
CapOrches is scientifically verified, mathematically ratified, and completely de-risked for Semester 2 production implementation.
Q1: "Why not simply use an existing workflow engine like Apache Airflow or Ray?" ▼
General-purpose orchestrators are schedulers, not resource optimizers—they treat tasks as black boxes and bind to pre-existing compute. Ray schedules CPU/GPU cores without model profile awareness. None solve joint model routing and instance provisioning under hard GPU budgets across concurrent workflow DAGs.
Q2: "Why treat reliability as an SLA floor constraint rather than optimizing it in the objective?" ▼
In enterprise cloud environments, reliability is a contract: an SLA requires 99.5% success. Achieving 99.9% provides diminishing returns, while dropping to 99.0% breaches contract. Objective weighting would require arbitrary dollar-per-reliability hyperparameters. Floor filtering preserves single-objective facility location with provable dual bounds.
Q3: "Why did you abandon scoped re-optimization after proposing it in Semester 1?" ▼
In Finding F18, empirical measurement revealed that profile sharing across concurrent workflows ranges from 84% to 100%. Because almost every workflow shares profiles, scoped re-optimization either cascades to touch all workflows anyway, or artificially constrains search space and worsens allocations. Global solving takes <60ms with C+cons, so scoped solving was dead-weight.
Q4: "What is the concrete advantage of Track B's Lagrangian relaxation if Track C is faster?" ▼
Track B is a high-fidelity dual bound generator. In optimization, you cannot know how good a heuristic is without a lower bound on the true optimum. While LP relaxation bounds are loose due to fractional instances, Track B preserves discrete integer instance step-functions, producing bounds that sit a paired 12.57 pp closer to optimum. Vectorized DP makes it evaluate in milliseconds.
